# Frontend work

Match the existing product style and the user's actual workflow. Build the
usable experience first, not a marketing page, unless the user asks for one.
Follow the project's design system and the user's explicit choices.

Prefer native controls and established app patterns: buttons for commands,
icons for common actions, checkboxes or toggles for binary choices, tabs for
views, and menus for option sets. Keep dimensions stable and responsive for
boards, toolbars, grids, cards, and fixed-format elements.

Keep layouts practical and readable. Avoid unnecessary nested cards,
decorative filler, and one-note color palettes. Text should fit its container,
and UI elements should remain usable without overlap at mobile and desktop
sizes. Use real or generated visual assets when the result depends on visual
inspection.

Check the changed interface at relevant narrow and wide sizes and exercise
its main interaction. Report any visual behavior you could not verify.
