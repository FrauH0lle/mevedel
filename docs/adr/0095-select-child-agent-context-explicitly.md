# Select child-agent context explicitly

Status: accepted

`Agent` has required `task_name` and `message` fields plus optional `role`, `context`, `model`, and `effort`; `context` replaces `fork_turns` without an alias. Omitted or `none` context isolates the child, `all` and positive decimal values copy an immutable selection from the parent's effective model-visible context, and `summary` generates a handoff context summary from context frozen when the Agent handler begins without copying a verbatim parent tail. The snapshot includes already-realized material from the active parent turn, excludes the triggering Agent call, and never waits for sibling work or later parent material. Summary preparation reserves the child path and capacity slot without publishing an addressable identity, runs the child's ordinary task hooks once, and focuses the summary on the resulting hook-accepted task; dispatch does not rerun those hooks. Failure or cancellation releases the reservation, cancels the summary request, suppresses late callbacks, and cannot spawn a child. Copied turns remain dialogue, while a summary is durably stored as labelled conversation context immediately before the initial Agent task, never in the child's frozen system configuration; the generated background may be stale or untrusted, and the separately supplied task remains authoritative. The child transcript is the canonical summary-content surface; the parent records only preparation metadata and the child link, leaving its model context unchanged. Follow-ups retain the background, later child compaction may absorb it into a continuation context summary, and neither context form synchronizes later parent turns.
