# Keep directive activity outside main chat

Status: superseded by ADR 0091.

Directive responses and follow-up discussion live in a workspace-owned directive activity surface with its own local composer rather than becoming ordinary main-chat conversation. Directive requests neither consume nor contribute main-chat context; the session records only a compact directive event linking to the full activity so chronological ordering and Rewind remain visible. The first model request binds the directive to its execution session, which is shown in activity and reused for later requests rather than following whichever workspace session was used most recently; workspace ownership of the directive does not change. A closed persisted execution session resumes on demand. If it is unavailable, mevedel requires explicit warned rebinding rather than silently splitting the history; prior attempts keep their unavailable historical checkpoint links. Implement this starts a new implementation attempt with the directive request, freshly resolved references, and the complete directive-local discussion; no directive-specific summary mechanism is introduced. After an implementation attempt, Discuss result continues the same read-only local discussion with that attempt attached, and Implement this uses the resulting discussion as feedback for a new implementation attempt. This preserves directive isolation while giving discussion an explicit continuation path and keeping detached or source-missing directives usable.
