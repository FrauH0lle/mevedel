# Relay and browser viewer

These instructions apply to `relay/` and its descendants.

Read [README.md](README.md) for the wire and build contracts and
[browser collaboration](../docs/collaboration.md) for host/browser authority
and session behavior.

- Keep the relay content-blind: it routes sealed payloads without the room
  key. The Emacs host owns session state, permissions, and execution.
- Coordinate sealed payload changes with the Emacs host and viewer callers.
- Viewer assets are embedded in the Go binary. Rebuild the relay after
  changing them; reload browser tabs to use the updated viewer.
- `viewer/shared-editor.js` and its license notice are generated by
  `shared-editing/build.mjs`. For changes to those outputs, read
  [shared-editing/AGENTS.md](../shared-editing/AGENTS.md), edit the source,
  and rebuild.

## Checks

For Go changes, run `go vet ./...` and `go test ./...` from `relay/`;
use `go build .` to rebuild the binary.

For viewer JavaScript changes, run
`node test/collaboration-viewer-test.js` from the repository root.
For shared-editor integration changes, also use the
[shared-editing checks](../docs/shared-editing.md#checks).
Host-side Elisp checks follow [the development guide](../docs/development.md).
