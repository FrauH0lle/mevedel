# Separate applying draft wording from committing it

**User correction, 2026-11-17:** after the assistant committed the pair skill before the user had approved its wording, the user said, “now you were a bit too fast.” The user subsequently confirmed: “Apply the changes but no commit yet.”

When collaboratively drafting or revising skill wording that is still under review, distinguish permission to apply the edits from approval to commit them. Keep the draft available for review and hold the commit until the wording is approved or the user explicitly authorizes committing it.

**Why:** committing a draft can prematurely finalize wording the user is still evaluating.

This correction does not establish a standing approval gate for every ordinary code commit. Follow the current task's instructions and any explicit approval phase.
