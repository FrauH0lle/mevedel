## Standards

No hard documented-standard violation was established. The following are
engineering judgments supported by measurements, rather than style objections.
Full evidence is in the [Standards report](claude-review-standards.md).

1. **P2 — Every request repeats synchronous readiness checks.**
   `mevedel-claude-code.el:535-545` runs four version probes and authentication
   status before root, directive, child, and isolated workload startup. Three
   measurements of the five sequential commands took 0.302, 0.301, and 0.305
   seconds, excluding ACP startup and the Emacs helper's output drain. The
   helper allows process callbacks while waiting but does not return to the
   editor command loop. Naming, guardians, and summaries repeat the work.
   Move preparation to the existing asynchronous startup boundary and cache
   version results against executable identity. Preserve current-login checks
   and explicit billing-route failures.

2. **P2 — Native history validation becomes quadratic as calls accumulate.**
   `mevedel-session-codec.el:702-708` searches a growing list to reject each
   duplicate native call ID. The complete compiled validator took 2.35 ms for
   1,000 IDs, 56.37 ms for 5,000, and 234.43 ms for 10,000, per validation,
   without GC. Replace the local seen-ID list with an `equal` hash table. This
   is a reopen/validation finding; the validator was not shown to run at every
   tool admission. Separately, the PID-lock sidecar publisher builds and prints
   the same sidecar twice at `mevedel-session-artifacts.el:2023-2027`; reuse its
   already-built artifact. That duplicate work is a small additional
   simplification, not a separately measured end-to-end bottleneck.

The shared engine context has multiple real callers and retains native gptel
state rather than fabricating it. Request admission, tool effects, and terminal
publication remain in existing owners. Broad abstraction removal would undo
useful locality. Likewise, the migration converter has a recorded explicit user
exception; it is not an unauthorized compatibility layer.

## Spec

These three gaps concern history, accounting, and canonical transcript
behavior. The [Spec report](claude-review-spec.md) includes quoted requirements,
source traces, and reproductions.

1. **P2 — Editing a retained child's transcript does not fence native resume.**
   `mevedel-claude-code-agent.el:89-95` resumes the native ID without the root
   divergence check. Live child buffers are writable and have no scope-aware
   history-edit observer. A real subprocess test changed the settled answer,
   followed up through the ordinary agent interface, and proved the original
   native ID resumed while the displayed transcript retained the edit.
   Make observation, submitted-input boundaries, and continuation checks apply
   to the child's scope; keep divergence through settlement. Use the existing
   explicit child excerpt-recovery flow. This does not require disabling child
   editing or follow-ups.

2. **P2 — Unknown native Goal usage is charged as one token.**
   The new ACP accounting caller at `mevedel-acp-turn.el:129` uses the shared
   fallback at `mevedel-goal.el:660-664`. That fallback estimates gptel's `:data`,
   which ACP never supplies. A 40,000-character native prompt with no reported
   usage charged exactly one token and left a 100-token Goal active. Preserve
   unknown usage explicitly, or derive a clearly labelled conservative
   estimate from actual native input/output. Budgeted continuation must not
   claim supported consumption from a placeholder; ordinary unbudgeted Goal
   work should remain available.

3. **P2 — Initial native reminders become Base64 user prose after a root turn.**
   The new typed-record emission at `mevedel-claude-code-context.el:248-254`
   exposes an existing assumption in `mevedel-transcript.el:1081-1098`:
   reconstruction after a completed-turn marker overlays the entire prefix as
   user text, swallowing trusted ignored reminder records. Two ordinary root
   sends reproduce it. The changed path instruction is acknowledged and its
   audit record remains trusted, yet canonical evidence contains encoded data
   instead of the decoded reminder. Preserve validated audit spans when
   reconstructing that user prefix. Cover subsequent turns, save/reopen,
   rendered reminders, and evidence used for history transfer.

## Transport correctness

The [transport report](claude-review-transport.md) retains dependency hashes,
precise conditions, and failed expected-behavior regressions. These are
additional correctness findings, separate from the three above.

1. **P1 — Ordinary TRAMP waits can permanently stall ACP delivery.**
   The connection boundary at `mevedel-acp.el:137-150` leaves ACP's private
   message-drain timer outside mevedel's transport ownership. When output
   arrives during `with-tramp-suspended-timers`, the newly scheduled timer can
   disappear with the temporary timer list while ACP's queue remains busy.
   Subsequent frames cannot restart the drain. A real subprocess test using
   the production remote-operation wrapper receives bytes but never completes;
   reactivating only the lost timer immediately completes it. Integrate drain
   scheduling with transport-owned timers before notifications reach
   `mevedel-acp-turn`. Its current callback-level deferral is too late. The
   separate exclusive-connection wrapper already preserves new timers and is
   not the affected path.

2. **P1 — A stale startup watchdog can close a healthy conversation.**
   `mevedel-acp.el:164-166` unconditionally fails when its watchdog callback
   runs. Startup can complete while TRAMP hides the original timer list;
   cancellation clears the connection slot but cannot remove that hidden
   timer. Once restored, it fires at the original deadline and closes a healthy
   connection with “ACP startup timed out.” A real-peer test reaches ready and
   idle, then fails after the shortened watchdog deadline. Check current state
   and captured timer ownership in the callback. Apply the same rule to the
   cancellation watchdog. Fixing drain scheduling alone does not fix this.

3. **P2 — Cancellation discards known terminal usage.**
   `mevedel-acp-turn.el:153-161` drops the queued terminal acknowledgement once
   the owner is cancelled, bypassing final usage normalization/merging.
   A public-abort reproduction proves final input 45/output 20 reached the
   adapter outcome, but settled request accounting retained input 10/output 1
   from the earlier stream snapshot. Preserve terminal accounting and
   once-only settlement for the cancelled owner while continuing to reject
   new work. This is separate from the unknown-usage fallback: these counters
   are known and available.

terminal usage and transcript/history fidelity, and make unknown budget usage
honest. Update the stale restart assertion to decoded evidence while retaining
its semantic check. Finally remove repeated readiness work and quadratic
validation, using the retained measurements as baselines. All fixes can stay
inside existing modules; no feature removal or broad framework is needed.
