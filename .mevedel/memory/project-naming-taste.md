# Project naming taste

User statements and correction recorded 2026-11-08 during mevedel naming exploration:

- A name that simply sounds good is valid; it need not encode the architecture.
- The user considers **gptel, Magit, and Spacemacs** good names, but not **Doom Emacs**.
- By sound, the user liked **Loom, Tinker, Ember, Bonsai, and Kaizen**. These are taste examples, not a chosen name or an approved shortlist.
- **Kestrel, Rook, Argo, Mako, and Vela** felt forced. Literal compounds such as **agentel/chatmacs** felt less forced but sounded bad.
- The user rejected sound-alike variations such as **Lume, Plume, Rune**, person/pet names, and invented two-syllable names in this exploration.
- A Japanese feel is appealing but should not be overemphasized.

Additional user statements captured in the naming digest created 2026-11-09, from the 2026-11-07 naming session:

- The user marked **Moss, Niwa, and Wabi** positively; **Distill, Grove, Kumiko, Mori, Sashiko, Shokunin, Faden, and Hain** were maybes.
- Nearly all proposed craft-verb names, such as **Tend, Graft, Whittle, and Lathe**, were rejected in that round.
- The user liked **Niwa and Loom**, but noted that they were “not really connected to what the package does.” Functional relevance therefore matters too; do not interpret the earlier sound preference as indifference to meaning.

**Correction:** Spacemacs is not a hidden-letters trick. Its name connects the space leader key with Emacs, combining good sound with a real deeper meaning. Merely finding “ai” inside words such as Bonsai or Kaizen is weaker; do not use letter-hiding as equivalent justification.

Apply these as starting points for future naming discussions, not universal bans on every name in a category. Good sound need not literally encode architecture, but a meaningful rationale should connect genuinely to the package. The assistant's hypotheses about a calm, hands-on tone or a nature/quiet-growth aesthetic were interpretations, not confirmed user preferences. Presenting sound before rationale was also an assistant approach, not an explicit user instruction.

No name was selected in this evidence. Collision research was reported in the digest created 2026-11-09, but those dated results are not current availability guarantees; repeat relevant checks before recommending adoption.
